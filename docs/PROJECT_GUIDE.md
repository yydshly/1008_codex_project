# 子项目研究指南

这个仓库集中记录优秀 GitHub 项目的研究、复现和演示。根 README 帮助读者按编号找到项目；详细分析放在各子项目内。

## 新增一个研究项目

在仓库根目录运行：

```powershell
npm run project:add -- --slug repo-name --name "项目名称" --upstream "https://github.com/owner/repo" --summary "一句话说明项目价值与研究重点"
```

脚本取已有最大编号加一，从 `templates/project/` 复制模板，替换项目编号、名称、目录名、原库链接和摘要，再更新 `projects.json` 与 README 中的自动生成区域。首次新增项目使用 `001`。

```text
projects/001-repo-name/
├── README.md     # 项目概览、研究结论、运行方式和演示入口
├── notes.md      # 研究过程、实验记录、问题和后续计划
├── assets/       # 封面、截图、图表等项目资料
├── src/          # 复现代码、实验脚本或明确标注来源的代码
└── web/          # 可选 Web 演示；没有演示时保留占位
```

### 编号与排序

- `id` 使用至少三位的数字字符串，例如 `001`、`002`；首页按编号数值升序展示。
- 编号一经分配保持不变。归档时保留索引条目，将状态改为 `已归档`，已使用编号不再复用。
- 目录名统一为 `<id>-<slug>`，`slug` 使用小写英文和短横线。
- 修改显示名称只需改 `name`。修改 `slug` 时同时调整目录、图片路径、文档链接和演示路径，保留原编号。

## 维护首页索引

根目录的 `projects.json` 是唯一索引数据源，结构为 `{ "schemaVersion": 1, "projects": [] }`。不要直接修改 README 的自动生成区域。

每个条目的字段如下：

| 字段 | 用途 |
| --- | --- |
| `id`、`slug` | 稳定编号与目录名称 |
| `name`、`summary` | 显示名称与一句话摘要 |
| `summaryItems` | 可选的分项摘要：`[{ "title": "能力", "text": "交互沙盘" }]`；首页将标题加粗并分行显示，未填写时使用 `summary` |
| `overviewItems` | 可选的引导图前介绍：`[{ "title": "定位与能力", "text": "项目能帮助谁完成什么" }]`；README 按段落展示，已发布网页总入口复用同一数据 |
| `upstream` | 被研究的原 GitHub 仓库链接；索引来源链接自动显示源库自己的名称，例如 Sandboard |
| `status` | `待研究`、`研究中`、`已完成` 或 `已归档` |
| `tags` | 技术、领域或研究方向标签数组 |
| `cover` | 相对仓库根目录的封面文件路径；无图片时为 `""` |
| `coverAlt`、`coverCaption` | 图片替代文本与图注；无图片时为 `""` |
| `coverFull` | 可选的完整高清图路径，须在本项目 `assets/` 内；填写后，封面链接高清图，并显示研究说明和在线入口 |
| `demo` | 已验证可访问的在线演示 URL；未部署时为 `""` |

更新信息或添加图片后运行：

```powershell
npm run index:build
npm run check
```

将 `projects.json`、生成的根 README 与对应子项目资料一起提交。`check` 验证仓库结构和索引；子项目自己的构建、测试和运行验证仍需在其目录执行。

## 研究记录的基本要求

在子项目 README 中写清研究对象、原库链接、研究目标、进展和结论；至少记录原库的完整 commit SHA、对应 tag 或版本（如有）、研究日期及许可证文件位置。研究基线固定到具体 commit，后续更新原库时补记新旧 commit 和结论变化。

在 `notes.md` 中按日期记录实验。每次实验包含目的、环境与依赖版本、执行命令、输入、观察结果及解释；失败的尝试也记录可复现的问题。区分原库已有能力、自己的复现结果和仍待验证的推测，避免把尚未完成的研究写成结论。

在 `src/` 中注明代码来源：独立实验、参考实现、原库摘录或修改副本。引入原库文件时保留其许可证和版权声明，记录来源路径、commit 与修改内容。当前仓库的说明和代码不自动改变上游代码的许可条件；未明确许可时，先以链接和自己的研究记录组织资料。

## 图片与图注

项目图片放在对应 `assets/` 内，建议封面使用 `cover.png` 或 `cover.webp`。例如：

```json
{
  "cover": "projects/001-repo-name/assets/cover.png",
  "coverAlt": "项目主界面展示搜索结果与详情面板",
  "coverCaption": "本地复现截图：搜索结果页，基于研究记录中固定的上游版本。"
}
```

图注说明画面展示什么、来源和版本背景。截图应来自真实复现；引用上游图片时标明原页面及来源。更详细的功能截图、对比图和实验说明放在子项目 README，首页保留一张封面和简短描述。

已有完整研究引导图时，可将 `cover` 设为整图的轻量预览、`coverFull` 设为高清原图。首页展示完整预览，不裁切；同一项目只展示一张引导图。`summaryItems` 用于索引表中的比较，`overviewItems` 用于图前的独立介绍，建议覆盖定位与能力、模块与原理、场景与产出、价值与复用、扩展与边界。介绍要说明读者能做什么、会留下什么结果，并用具体例子帮助选择入口；日期、尺寸和素材来源放在图下的 `coverCaption`，完整结论与试验记录放入子项目 README。未设置 `overviewItems` 的旧条目保持原有展示。

## 完成与归档

将状态改为 `已完成` 前，整理核心结论、复现步骤、已知限制和后续方向；有 Web 演示时按 [部署指南](DEPLOYMENT.md) 验证构建与访问。停止继续研究的项目改为 `已归档`，保留已有文档、代码与编号，说明归档原因。
