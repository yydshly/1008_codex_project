01 / TRAINING

“训练”里有几个不同的起点

参数最初从哪里来，与训练时更新多少参数，是两个不同问题。

先说结论

H3 的现成路径是微调；整个 Unsloth 的训练范围更广。

可以确认加载与运行、量化、LoRA / QLoRA、全参数微调和继续预训练等能力。本次没有核实通用的“随机权重 → 全新模型”完整入口，也没有发现从零训练 H3 的现成流程。因此不能写成“一键从零造模型”，也不把“绝对只能二次训练”当作整个库的永久结论。

02 / CAPABILITIES

从模型到应用，它能参与哪些环节？

当前项目包括 Python 训练核心、Web 工作台和桌面应用。具体模型、训练方法与运行后端需要逐项匹配。

平台支持要按任务看

官方覆盖 Windows、Linux、macOS 及不同 GPU / 后端。CPU 可承担部分聊天和数据工作；GPU 训练、MLX、GGUF 推理有各自条件。“可以启动工作台”不等于“这台设备能训练选中的模型”。

让 H3 更贴近品牌产品短片

准备产品近景、对应动作与有效声音的短片，附上准确描述。训练目标是学习这些素材的局部画面与声音特征；再用未出现过的提示词评估风格、产品一致性和声画效果。

  2. 处理预处理 / 编码 → 联合音视频 LoRA
  3. 产物基础 H3 + 新适配器
  4. 验证新提示词生成，检查目标与原有能力
22 帧当前训练窗口约 0.92 秒

源码按 24fps 的固定短窗处理。较长视频只取开头，需先切片并让描述对应这个窗口。

音视频联合素材必须带有效声音

视频与音频共享一套块权重。数据检查拒绝无音轨和全静音素材，不能用静态图片替代。

约 80GB+源码标注的整流程训练参考

编码器阶段也会抬高峰值。这是当前实现的参考口径；本项目没有 GPU 实测，不由量化文件体积推算显存。

H3 还有哪些具体实现边界？
  • 已确认的训练布局是文字生成音视频（t2va），不是对全部参考输入模式逐一验证过的训练方案。
  • 当前路径要求 bf16 混合精度、批量大小为 1；可以通过梯度累积调整有效批量。
  • 训练底座可配置 NF4、INT8、BF16 等路径；当前实现拒绝 FP8 / MXFP8 训练，不能直接把 FP8 推理包当训练承诺。
  • 保存的 LoRA 有专门加载方式；当前路径没有完整的周期检查点 / 恢复支持，需要核对所用版本。
  • 官方完整 H3 系统包含 Context-IR、H3-Base 与 2K 再生成模块。开放的基础权重与整套在线系统的能力范围需分别确认。
  • 从零训练 H3 需要另外实现初始化、数据、损失与训练工程；这里的现成入口加载已有权重并训练增量。

06 / WORKFLOW

一次有意义的微调，应该怎么落地？

训练命令只是一环。先定义成功标准，才知道额外训练是否值得。

  1. 01

    定义任务，先建立基线

    选定可获取权重、许可与后端匹配的基础模型。用提示词直接测任务，记录错误类型，确认是否需要训练。

  2. 02

    准备能表达目标的数据

    清洗、去重、标注并覆盖真实输入。任务微调使用输入输出样例，继续预训练使用语料，RL 需要奖励，H3 使用带声音的短片与描述。

  3. 03

    先划分测试集，再开始训练

    保留未参与训练的样本，避免同一事件或相似素材落入两边。定义格式、任务正确率、风格与原有能力的评估。

  4. 04

    选择方法与资源，进行小实验

    从合适的 LoRA / QLoRA 基线开始，记录版本、精度、长度、r、有效批量和训练时间。遇到资源问题先定位最大开销。

  5. 05

    与原模型比较，检查退化

    使用同一测试集与生成设置，评估收益、错误与原有能力。训练 loss 下降不能独立证明业务效果改善。

  6. 06

    保存、部署，并验证整条链

    明确保存的是适配器还是完整模型。检查基础权重版本、模板、终止标记和后端支持，在实际应用中重测输出。

07 / LIMITS

它降低成本，但这些条件仍然存在

官方性能数字与本项目的机制示意采用不同口径；页面没有执行真实训练或重现上游 GPU 基准。

数据决定学习目标

低质量、错误或高度重复的数据会教给模型相应偏差。数据代表性、测试集独立性与任务评估比“训练成功结束”更重要。

支持范围随版本变化

模型能下载、能运行、能加载 LoRA、能训练 LoRA、能全参数训练，是不同层级。逐个核对架构、模型变体与所用后端。

显存要算完整流程

权重、编码器、激活、梯度、优化器状态与 KV cache 都可能影响峰值。磁盘文件体积、某一步内存与整流程峰值也不同。

权重与工具许可分开

Core 采用 Apache-2.0；Studio 的相关组件采用 AGPL-3.0。模型权重遵循自身许可，工具的许可不会替代模型许可。

查看对应许可原文

怎么看“2 倍速度、少 70% 显存”？

仓库的这类数字是官方在特定条件下的宣传与基准。应同时记录模型、GPU、软件版本、精度、上下文、有效批量、数据集与比较基线。MoE 的倍率还涉及 Transformers 版本差异；单个内核加速不能直接推算端到端训练时间。
