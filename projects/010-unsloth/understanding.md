## 十二项摘要

### 定位

围绕已有开放权重模型的训练与运行工具：Core 提供 Python 优化，Studio / Desktop 提供工作台；重点是更低成本地把通用模型适配到自己的任务。

### 能力

加载推理、量化、LoRA / QLoRA、全参数微调、继续预训练、DPO / GRPO 等后训练、部分多模态适配、保存导出与应用连接；每项需匹配模型、格式和后端。

### 模块

按职责理解为模型加载适配、数据模板、训练方法、计算内核、显存与批次调度、多模态专用路径、保存导出、运行工作台八部分；依托 PyTorch、Transformers、PEFT、TRL 等生态。

### 训练原理

LoRA 冻结底座并学习低秩增量，QLoRA 量化冻结权重以减少存储；SFT 从样例学习任务，继续预训练学习语料，偏好与强化学习按选择或奖励更新。微调本身就是训练。

### 效率原理

模型计算补丁、Triton 融合内核与定制反向减少搬运和临时张量；分块损失、梯度检查点与卸载降低峰值，packing 减少填充，部分 RL 路径复用推理和训练资源。

### 代表模型

文本 Qwen / Llama / Gemma / Phi / Mistral，MoE 与专门架构 gpt-oss / Qwen MoE，视觉语言、Whisper / Orpheus / CSM 语音、部分图像扩散、MiniMax H3 音视频和 EmbeddingGemma；列举不等于全部训练方式通用。

### H3 案例

提供 GGUF、FP8 / INT8 运行版本；固定源码的训练路径加载预训练 H3，冻结底座后训练音视频 LoRA。要求有声音的视频与描述，22 帧约 0.92 秒窗口，整流程资源参考约 80GB+，未本机实测。

### 场景

客服表达与流程、分类抽取与 JSON、领域语言、代码规范及可评分任务、视觉和语音适配、品牌音视频风格实验；经常更新的事实优先检索 / 工具，按需叠加行为微调。

### 价值

降低定制实验的显存压力和迭代成本，保存可复用适配器，增加本地运行与交付选择；对本仓库可用于研究内容表达、资料抽取和应用原型，效果与节省比例均需独立评测。

### 复用路线

可只用量化模型本地运行，或以小型文本模型做单任务 LoRA，再接检索与业务应用，最后探索视觉 / 语音 / H3；先建立原模型基线、独立测试集和可比较的结果。

### 扩展方向

版本化数据集、模型支持矩阵、可复现实验台、适配器注册表、RAG + 微调组合、行业任务包、多模态素材管线、任务队列与成本观测八项；均为后续开发建议。

### 边界与许可

本次未核实通用随机初始化完整入口，H3 已确认路径是二次训练；不能宣传一键从零造模型，也不能说不支持训练。固定 f9718db；Core Apache-2.0、Studio AGPL-3.0，权重独立许可；本站只验证研究网页。

## 图前介绍

### 它解决什么问题

你已经有一个基础模型，但希望它更遵守自己的格式、术语、任务或风格。Unsloth 优化加载、适配与训练过程，让定制实验更容易开展；模型是否学好仍由数据、目标和评测决定。

### 从哪里开始

加载权重是使用已有参数，量化是改变存储表示，微调是更新参数，二次开发是围绕模型写应用。全参数微调也可以从已有权重开始；本次没有核实从随机参数得到全新模型的通用完整流程。

### 底层如何协作

Core 在支持的模型上接入 Transformers / PEFT，并替换热点计算；Triton 和自定义梯度减少临时开销，分块、检查点和卸载管理显存，紧凑批次减少填充，训练器完成数据与优化更新。

### 哪些模型与场景

文本、MoE、视觉语言、语音、向量和部分扩散模型有不同支持路径。客服、抽取、代码和风格适配可以做训练实验，实时文档问答可组合检索。H3 的量化运行与短片音视频 LoRA 是两条分别核对的路径。

### 对我的价值与顺序

把这份研究变成可执行的判断：先选一个可检验的小任务，测原模型，再准备独立样例训练 LoRA，比较正确性与成本，最后接入应用。可以沉淀个人数据集、适配器和评测资料，再决定是否投入复杂多模态训练。

## 能力

### 把通用模型变成任务模型

使用成对的输入与理想输出，训练分类、抽取、对话或代码任务。LoRA / QLoRA 是常见入口，全参数微调也是可选方法。

**例子**：订单描述 → 指定字段的 JSON

依据：[微调入门与数据准备](https://unsloth.ai/docs/get-started/fine-tuning-llms-guide.md)

### 学习偏好与可评分行为

DPO 适配回答偏好；GRPO 等强化学习方法让生成结果进入评分与更新循环。奖励函数与评估设计仍需自己准备。

**例子**：生成代码 → 测试评分 → 更新策略

依据：[强化学习中的显存复用](https://unsloth.ai/docs/get-started/reinforcement-learning-rl-guide/memory-efficient-rl.md)

### 继续学习原始语料

在已有基础模型上继续训练文本语料，例如学习新语言或领域表达。它与只训练问答格式的任务微调侧重点不同。

**例子**：领域语料 → 继续预训练 → 任务微调

依据：[继续预训练](https://unsloth.ai/docs/basics/continued-pretraining.md)

### 覆盖更多模态与模型

包括视觉语言、语音、Embedding 和部分扩散模型。视觉问答、语音任务、音视频生成的模型结构与数据集并不相同。

**例子**：票据图像 + 问题 → 字段；视频 + 描述 → H3 LoRA

依据：[视觉模型微调](https://unsloth.ai/docs/basics/vision-fine-tuning.md)

### 本地工作台与工具连接

Core 提供 Python 接口，Studio / Desktop 提供工作台。支持路径中可运行模型、使用 RAG / 工具，并通过兼容 API 连接应用。

**例子**：自己的模型 → 本地 API → 业务应用

依据：[仓库 README 与功能声明](https://github.com/unslothai/unsloth/blob/f9718db128218f43b7e0b03604baa4a9a6633028/README.md)

### 量化、保存与导出

保存适配器、合并支持的模型、导出 GGUF 等格式。运行端需要匹配模型结构、模板和终止标记；格式可导出不等于所有引擎可用。

**例子**：训练产物 → GGUF → 兼容的运行引擎

## 模块

### 01 · 模型加载与架构适配

读取已有权重、tokenizer / processor 与精度配置，在支持架构上接入快速计算；模型结构决定哪些补丁可以生效。

**输入**：模型标识、权重版本、设备与精度

**交付物**：可运行或可训练的模型对象

依据：[模型适配：llama.py](https://github.com/unslothai/unsloth/blob/f9718db128218f43b7e0b03604baa4a9a6633028/unsloth/models/llama.py)

### 02 · 数据、模板与任务组织

把原始文本或输入输出样例变成训练序列，处理 chat template、标签、长度与批次。模板错误可能使训练与部署行为不一致。

**输入**：语料 / 样例、字段映射、任务模板

**交付物**：经过检查的训练数据与独立测试集

依据：[微调入门与数据准备](https://unsloth.ai/docs/get-started/fine-tuning-llms-guide.md)

### 03 · 训练方法与生态接线

LoRA / QLoRA、全参数和继续预训练按方案更新；SFT、偏好与 RL 有不同数据或奖励要求。Trainer / TRL、PEFT 等提供训练生态接口，Unsloth 优化其中支持的路径。

**输入**：任务目标、训练配置、偏好或奖励

**交付物**：参数更新与训练记录

依据：[强化学习中的显存复用](https://unsloth.ai/docs/get-started/reinforcement-learning-rl-guide/memory-efficient-rl.md)

### 04 · GPU 内核与自动求导

优化 LoRA 的前向 / 反向、RoPE、MLP 和交叉熵等热点。Triton 融合与内存复用降低重复启动、搬运和临时结果；未适配的配置可回退。

**输入**：张量、模型结构、精度与设备

**交付物**：同一训练目标的优化计算路径

依据：[LoRA 前向与反向计算](https://github.com/unslothai/unsloth/blob/f9718db128218f43b7e0b03604baa4a9a6633028/unsloth/kernels/fast_lora.py)

### 05 · 显存与有效批次调度

组合激活重算、分块投影与损失、CPU 卸载、padding-free / packing。部分 RL 场景共享生成权重并安排缓存生命周期，分别解决不同峰值与浪费。

**输入**：序列长度、批量、缓存与显存预算

**交付物**：资源可承受的计算布局；实际峰值需测量

依据：[长上下文训练与内存调度](https://unsloth.ai/docs/blog/500k-context-length-fine-tuning)

### 06 · 多模态与专用训练器

视觉图文、语音和扩散训练需要各自编码器、数据与目标。H3 使用专门的 Diffusers / PEFT 音视频 LoRA 路径，不能套用文本模型的显存或格式经验。

**输入**：图像 / 音频 / 视频与对应描述

**交付物**：按模型支持范围训练的适配结果

依据：[H3 音视频 LoRA 训练器](https://github.com/unslothai/unsloth/blob/f9718db128218f43b7e0b03604baa4a9a6633028/studio/backend/core/training/diffusion_h3_trainer.py)

### 07 · 保存、合并与导出

保存适配器或完整权重，在支持路径中合并、量化或导出 GGUF。加载端还要匹配基础版本、架构、模板、终止标记；H3 适配器另有专用加载方式。

**输入**：训练结果与目标运行格式

**输入**：模型、数据、应用连接与设备

**交付物**：模型使用界面与服务接入

## 训练方式

- **加载与推理**：起点 已有模型；参数 不更新；目标 回答问题、生成内容。工作台可以加载权重，但加载本身不让模型学会新任务。
- **量化**：起点 已有权重；参数 改变数值表示；目标 降低存储与内存需求。压缩可能带来数值差异；不会自动获得新知识或新技能。
- **LoRA 微调**：起点 已有模型；参数 更新新增的小矩阵；目标 学习任务、风格与输出习惯。基础参数通常冻结；训练成果可以是一份适配器。
- **QLoRA 微调**：起点 量化的已有模型；参数 更新适配器；目标 在较少显存中做微调。基础权重低精度存储；适配器、计算与中间结果使用各自精度。
- **全参数微调**：起点 已有模型；参数 更新全部或大部分参数；目标 更广泛地适配任务。更新全部参数不等于随机初始化；显存与训练成本通常更高。
- **继续预训练**：起点 已有模型；参数 按训练方案更新；目标 继续学习原始语料、新语言或领域。仍然继承基础模型的已学能力；需防止原有能力退化。
- **偏好 / 强化学习**：起点 已有模型；参数 按偏好或奖励更新；目标 调整回答偏好、可验证行为。DPO 使用偏好样例；GRPO 等方法使用生成结果与奖励规则。
- **真正从零训练**：起点 随机初始化的参数；参数 学习基础能力；目标 创建一个新模型。本次未核实开源库的通用随机初始化入口；H3 现成路径是已有权重上的 LoRA。不能把总体“支持预训练”当作一键从零造模型的承诺。

## 底层原理

### 在已有能力上，学习一份小的增量

原模型权重 W₀ 保持冻结，只训练低秩矩阵 A、B。计算时使用 W₀ + sBA；s 是缩放系数。QLoRA 再压缩冻结权重的存储。

**说明**：低秩适配来自 LoRA / QLoRA 研究。Unsloth 的贡献是进一步优化这些计算与训练流程，并不意味着 LoRA 是它发明的。

**收益**：主要减少可训练部分的开销。基础模型、激活与缓存仍要占内存。

- 保留基础模型：继承原模型已经学习的通用能力。
- 添加低秩增量：用小矩阵表达任务相关的权重调整。
- 更新并保存适配器：减少可训练参数、梯度与优化器状态。
依据：[LoRA 前向与反向计算](https://github.com/unslothai/unsloth/blob/f9718db128218f43b7e0b03604baa4a9a6633028/unsloth/kernels/fast_lora.py)

### 合并运算，让数据少搬几次

Unsloth 对支持架构替换部分前向实现，使用 Triton 内核和定制 autograd 优化 LoRA、RoPE、MLP 与损失计算。

**说明**：这是实现层面的优化。部分不兼容配置会回退到普通计算，不能把某个内核的倍率当作整次训练的倍率。

**收益**：改善吞吐与内存读写。收益依赖架构、配置、GPU 和当前软件版本。

- 适配模型计算：接入 PyTorch / Transformers / PEFT，替换已支持的热点路径。
- 融合热点操作：例如合并 Q、K 的旋转位置编码，减少重复启动。
- 优化梯度与内存复用：用定制反向计算减少临时张量、复制与重复计算。
依据：[模型适配：llama.py](https://github.com/unslothai/unsloth/blob/f9718db128218f43b7e0b03604baa4a9a6633028/unsloth/models/llama.py)

### 改变中间结果的保存与处理时机

模型权重只是训练内存的一部分。激活、梯度、优化器状态和词表投影也会占据大量显存，长序列尤其明显。

**说明**：降低峰值与降低总计算量是不同概念。官方超长上下文案例指定了模型、训练模式与大显存 GPU，不能推导为所有模型都具备同样上下文能力。

**收益**：让更长序列或更大任务有机会装进显存。可能增加重算或传输开销。

- 少保存，按需重算：梯度检查点在反向传播时重算部分激活。
- 分块处理大张量：分块 LM head / 交叉熵与 Tiled MLP 降低同时驻留的规模。
- 把部分结果移到 CPU：在支持的路径中卸载激活，并安排异步传输。
依据：[长上下文训练与内存调度](https://unsloth.ai/docs/blog/500k-context-length-fine-tuning)

### 用有效样本填满计算位置

常规批处理会把短样本补到同批最长样本的长度。Padding-free 或 packing 减少这种空位，同时正确保留样本边界。

**说明**：显式 packing 可能改变每步有效 token 数和损失统计方式，比较训练结果时应固定数据、步数、有效批量及归一化口径。

**收益**：短样本多、长度差异大时更有价值。全是等长样本时收益会缩小。

- 统计样本实际长度：找到短样本补齐所产生的浪费。
- 组织紧凑的序列：减少补齐，或把样本组织到更紧凑的计算布局中。
- 保留掩码与位置关系：避免一条训练样本读取另一条样本。
依据：[RoPE 内核与 Padding-free / Packing](https://unsloth.ai/docs/blog/3x-faster-training-packing.md)

### 生成与更新交替进行，资源也可以交替使用

强化学习需要先生成候选结果，再评分并更新模型。推理缓存与训练激活如果同时保留，会显著抬高显存占用。

**说明**：奖励如何定义仍然决定模型学到什么。降低训练成本不会自动产生可靠的推理能力，也不能代替任务测试。

**收益**：减少重复权重和阶段切换开销，给生成长度或训练资源腾空间。

- 生成候选回答：用支持的推理引擎完成 rollout。
- 计算奖励并更新：奖励规则或验证器提供训练信号。
- 共享权重并调度缓存：支持的 vLLM 路径复用权重空间，Standby 调整缓存生命周期。
依据：[强化学习中的显存复用](https://unsloth.ai/docs/get-started/reinforcement-learning-rl-guide/memory-efficient-rl.md)

### 用更紧凑的数字表示已有权重

量化降低存储精度，使部分模型更容易在本地运行。动态混合精度会为不同部分选择不同精度，以平衡体积与数值差异。

**说明**：推理用的量化文件不能直接当作训练用底座。例如当前 H3 训练路径拒绝 FP8 / MXFP8 基础精度，允许的训练配置与 FP8 推理版本不同。

**收益**：主要服务存储与运行成本；量化本身不把新任务教给模型。

- 选择支持的量化版本：精度、模型架构与运行后端要匹配。
- 保留敏感部分：具体方案可以让部分层或参数保持较高精度。
- 重新评估输出：检查生成质量、速度和完整运行内存。
依据：[训练路由、资源说明与配置约束](https://github.com/unslothai/unsloth/blob/f9718db128218f43b7e0b03604baa4a9a6633028/studio/backend/core/training/diffusion_train_common.py)

## 可使用场景

### 客服话术与任务流程

让模型更倾向于遵守回答结构、术语和服务步骤。

**输入**：用户请求、业务上下文、理想回复；涉及政策时同时准备可检索资料。

**方法**：先整理高质量样例，再做 SFT / LoRA

**条件**：风格变得一致不代表业务事实就正确。政策、价格与库存等动态信息仍应从外部系统取。

**例子**：“订单延迟怎么办？” → 按公司的解释、核查和补救步骤组织回复。

### 分类与结构化抽取

提高字段格式与特定任务表现，便于接入应用。

**输入**：待处理文本、分类标签或字段 schema、人工核对后的正确输出。

**方法**：用明确的输入输出标准做任务微调

**条件**：接口仍应做 JSON 解析、字段校验与失败处理。先验证提示词方案，确认微调能带来实际增益。

**例子**：订单描述 → 商品、数量、地址；工单内容 → 问题类别。

### 经常更新的公司文档

回答时找到相关材料，并把依据提供给用户。

**输入**：带版本和权限的文档、切分与检索规则、引用与答案评估集。

**方法**：检索最新资料，按需叠加行为微调

**条件**：RAG 在回答时提供上下文，通常不改变模型权重。Unsloth 工作台有相关能力，但检索质量和权限边界仍需设计。

**例子**：“本月报销标准是什么？” → 检索当前制度后回答。

### 代码规范与可验证任务

适配代码风格，或改善能被准确评分的任务表现。

**输入**：代码规范与参考实现；测试、编译检查或其他可信验证器。

**方法**：先训练样例；奖励可靠时再做强化学习

**条件**：需要防止模型学会钻奖励规则的空子。未见过的任务、正确性和原有能力都要测。

**例子**：生成函数 → 执行测试 → 根据结果提供训练信号。

### H3 品牌音视频风格

尝试学习特定内容、画面与声音特征；效果需生成实测。

**输入**：有有效音轨的视频文件与 caption，预先切片使内容和文字对应。

**方法**：带声音的短视频 + 文字描述，训练适配器

**条件**：当前固定训练窗约 0.92 秒，整流程资源参考约 80GB+。不能把它当作完整长视频理解或剪辑方案。

**例子**：带声音的产品近景短片 + 描述 → 风格适配器。

### 从零造一个新模型

从数据中学习基础能力，而不是继承现成模型的能力。

**输入**：架构、随机初始化、编码器或 tokenizer、足量数据、训练目标、分布式方案。

**方法**：先定义模型、数据与训练方案，单独验证工具适配

**条件**：本次没有核实 Unsloth 的通用随机初始化训练入口。H3 已确认的现成训练路径是微调；若自行改造从零训练，需额外实现并验证。

**例子**：先在小模型上验证训练管线，再决定是否扩大规模。

## MiniMax H3 的已确认范围

H3 为音视频生成模型。GGUF / FP8 / INT8 推理包与可训练底座分别核对；现成训练器加载预训练基础权重，冻结底座并对 Attention / MLP 添加 LoRA，联合更新音视频目标。

素材需有有效声音的视频与对应 caption；固定 22 帧、24fps、约 0.92 秒窗口。当前训练配置为 bf16、batch 1，可梯度累积；拒绝 FP8 / MXFP8 训练，NF4 / INT8 / BF16 等路径分别配置。整流程约 80GB+ 为源码参考，编码器阶段影响峰值，本项目没有 GPU 实测。

已确认 t2va 训练布局，未逐一验证所有参考模态。适配器有专用加载方式，当前没有完整周期检查点 / 恢复支持。完整官方系统中的 Context-IR、H3-Base 与 2K 模块的开放范围分别确认；这里没有现成从零训练 H3 的验证结果。

## 价值与个人意义

### 显存与实验成本

适配器减少可训练状态，计算与内存优化提高资源利用率，有机会在现有 GPU 上做原本难以进行的实验。实际成本需包含数据、租卡、验证、存储与部署。

**验收依据**：在相同任务和配置下记录峰值、有效 token 吞吐、总时间和测试结果。

### 更快验证任务适配

把格式、语气、术语和任务步骤写成样例，低成本试出微调是否优于提示词。失败实验也能帮助识别底座能力、数据与任务定义的问题。

**验收依据**：原模型与微调模型使用同一独立测试集，比较正确率、格式合规和退化。

### 可复用的模型资产

保存一份适配器、基础模型版本、数据版本与评测记录，形成能重载和交接的任务资产；适配器不能脱离匹配底座随意使用。

**验收依据**：在新的环境中重载，并复现代表样例与评测口径。

### 自己的研究资料工作流

对本仓库，可尝试把 GitHub 研究整理成固定中文摘要、模块字段、来源清单和结构化资料。事实仍从代码与资料核对，模型训练主要适配表达与抽取行为。

**验收依据**：人工核对出处、字段遗漏、错误率和修改时间；不得把猜测变成研究事实。

### 应用与本地控制

在设备允许时本地运行，并将模型接入网页、检索和业务工具。它提供更多交付选择，应用仍需自己实现状态、权限、错误处理和结果校验。

**验收依据**：在真实输入和完整服务链中评估质量、延迟与资源占用。

### 学习模型工程的入口

从 W₀ + sBA 理解参数更新，再观察显存构成、批次组织、梯度和导出流程。先掌握小型文本任务，再判断是否值得进入 H3 等复杂多模态工程。

**验收依据**：能解释数据→损失→更新→产物→部署，并用对照实验支持自己的判断。

## 复用路线

### 路线 A · 先使用现成模型

选可运行的量化变体，先做提示词、检索或工具连接。适合需求尚未确定、样例不足，或原模型已能完成任务的阶段。

**交付物**：模型选择表、任务基线与运行原型

**验收依据**：质量达标，完整内存、延迟和模板可复现。

### 路线 B · 一个小任务的 LoRA

选可获取权重的小型文本模型，准备代表样例与独立测试集，从输出格式或分类抽取开始。先跑少量训练，确认增益，再扩大样本与配置。

**交付物**：适配器、数据与版本记录、对照报告

**验收依据**：新样例效果改善，原有能力与成本在可接受范围。

### 路线 C · 检索 + 行为微调 + 应用

外部检索提供最新资料，工具获取实时状态，微调适配回答格式和操作步骤。把模型接到自己的网页或服务，并对字段、引用和工具结果做校验。

**交付物**：有出处的知识应用与可验证任务流程

**验收依据**：资料更新生效、引用正确、失败可处理；独立测试通过。

### 路线 D · 按资源探索多模态

分别准备视觉图文、语音或带声音的 H3 短视频数据。先确认已有模型与训练器支持、许可和资源，再用小批素材判断能否学习目标特征。

**交付物**：素材规范、专用训练配置与生成对照

**验收依据**：未见过的素材或提示词达到目标；显存与声画等指标有实测。

## 推进顺序

### 第一步 · 明确一个可检验任务

例如研究摘要的字段抽取。先定义输入、正确输出与验收，用原模型建立基线，判断提示词或检索是否已足够。

### 第二步 · 做一次小型对照实验

准备代表样例与独立测试集，选择兼容的小型文本模型和 LoRA / QLoRA。记录版本与成本，用未见过的样例比较收益与退化。

### 第三步 · 再决定交付与扩大

只有效果和成本达到目标才接入自己的网页 / API，保存适配器与重载说明；然后按实际需求扩展数据、任务或多模态，不必从 H3 开始。

## 常见疑问

### 它的核心价值到底是什么？

让已经存在的模型更便宜、更方便地训练和运行。对于业务定制，价值是缩短实验周期、降低显存需求；最终任务效果由基础模型、数据、训练方案和评估共同决定。

### “只能加载或者二次训练”这样说对吗？

可以用它描述本次确认的主要使用方式，尤其是 H3 的现成路径。但对整个 Unsloth 下“绝对不能从零训练”的结论过于宽泛。需要区分公开的完整工作流、某个模型的适配，以及自己修改后可能实现的训练工程。

### “加重”是不是指加载权重？

这里按“加载模型权重”理解：把训练好的参数读到运行环境中。加载、量化和训练是三件事。只有进入参数更新过程，模型才在训练意义上学习新的数据。

### 全参数微调是不是从零训练？

不是同一个起点。全参数微调可以更新整个已有模型，而从零训练通常从随机参数开始。更新多少参数和参数最初从哪里来，是两个不同维度。

### 训练完是否得到一份独立模型？

LoRA 常得到一份适配器，运行时还需要对应基础模型。部分模型支持合并权重；是否能合并、导出到目标格式和加载到运行后端，需要逐个确认。

### 上传 PDF 就会自动学会全部内容吗？

PDF 可以作为数据来源，也可以参与检索。训练还需要提取、清洗、定义任务与评估。频繁变化的事实通常更适合通过检索或业务接口提供；微调可以叠加学习回答方式。

### 可以训练我通过 API 使用的模型吗？

远程生成接口只提供调用能力。Unsloth 的本地权重训练需要能获取并加载兼容权重。供应商若提供专门微调服务，应遵循它的接口与支持范围。

### 压缩版 H3 体积小，训练就一定轻吗？

推理量化文件、训练底座和全流程内存是不同口径。H3 还有文本编码器、视觉 / 音频 VAE、激活与优化器状态。仅查看某个去噪器文件大小会低估资源需求。

### 官方“2 倍速度、少 70% 显存”能直接套用吗？

这是官方特定条件下的宣传与测试结果，本项目没有 GPU 实测。比较时要记录模型、GPU、软件版本、精度、长度、有效批量、数据与基线；不能把不同优化的倍率直接相乘。

### 二次开发和二次训练有什么区别？

二次开发是写网页、接口、工具和业务流程，可以不改模型参数；二次训练是根据数据或奖励更新模型参数。两者可以结合，但解决的问题不同。

- [仓库 README 与功能声明](https://github.com/unslothai/unsloth/blob/f9718db128218f43b7e0b03604baa4a9a6633028/README.md)：Core / Studio / Desktop、运行与训练范围。README 的总体支持声明不等于每个模型都具备每种能力。
- [模型适配：llama.py](https://github.com/unslothai/unsloth/blob/f9718db128218f43b7e0b03604baa4a9a6633028/unsloth/models/llama.py)：pre_patch 替换部分前向实现；接入 Transformers、PEFT 和量化配置。
- [LoRA 前向与反向计算](https://github.com/unslothai/unsloth/blob/f9718db128218f43b7e0b03604baa4a9a6633028/unsloth/kernels/fast_lora.py)：LoRA_MLP、LoRA_QKV 和自定义 autograd；部分配置会回退到普通实现。
- [交叉熵 Triton 内核](https://github.com/unslothai/unsloth/blob/f9718db128218f43b7e0b03604baa4a9a6633028/unsloth/kernels/cross_entropy_loss.py)：融合损失计算、分块 logsumexp、定制梯度。与长序列分块损失优化一起理解。
- [LoRA 原论文](https://arxiv.org/abs/2106.09685)：低秩适配来自 LoRA 研究。网页中的参数数量是矩阵维度计算示意。
- [QLoRA 原论文](https://arxiv.org/abs/2305.14314)：量化冻结基础权重，同时训练适配器；4-bit 存储与实际计算精度需要区分。
- [RoPE 内核与 Padding-free / Packing](https://unsloth.ai/docs/blog/3x-faster-training-packing.md)：合并 Q/K RoPE、减少复制；保留序列边界以避免样本间注意力泄漏。
- [长上下文训练与内存调度](https://unsloth.ai/docs/blog/500k-context-length-fine-tuning)：分块 LM head / 损失、激活卸载、梯度检查点和 Tiled MLP。官方 500K 示例有指定模型与硬件前提。
- [强化学习中的显存复用](https://unsloth.ai/docs/get-started/reinforcement-learning-rl-guide/memory-efficient-rl.md)：支持路径中共享 vLLM 权重存储，Standby 调度推理缓存与训练资源。
- [继续预训练](https://unsloth.ai/docs/basics/continued-pretraining.md)：在已有模型上继续训练原始语料，例如新语言。该教程不等于从随机权重训练的教程。
- [微调入门与数据准备](https://unsloth.ai/docs/get-started/fine-tuning-llms-guide.md)：数据、训练与评估流程。应用选择卡是本项目基于机制的判断，不是官方效果保证。
- [硬件与运行要求](https://unsloth.ai/docs/get-started/fine-tuning-for-beginners/unsloth-requirements)：不同界面与后端的支持情况；显存表是最低参考，不能代替具体配置实测。
- [官方模型目录与量化变体](https://unsloth.ai/docs/get-started/unsloth-model-catalog.md)：总览图中的代表模型：文本、MoE、视觉和向量模型。目录里的运行格式不构成所有训练方式均受支持的承诺。
- [语音生成与识别微调](https://unsloth.ai/docs/basics/text-to-speech-tts-fine-tuning.md)：Whisper STT、Orpheus、Sesame-CSM 等训练示例；基础权重与具体配置需匹配。
- [保存与导出 GGUF](https://unsloth.ai/docs/basics/inference-and-deployment/saving-to-gguf)：导出、合并和运行；跨框架需保留训练时的 chat template 和终止标记。
- [视觉模型微调](https://unsloth.ai/docs/basics/vision-fine-tuning.md)：视觉语言模型的图像与文本样例适配；与 H3 的音视频生成训练不同。
- [MoE 训练与基准比较](https://unsloth.ai/docs/basics/faster-moe.md)：Grouped GEMM 与 LoRA 优化；宣传倍率依赖 Transformers 版本及比较基线。
- [本地扩散模型工作流](https://unsloth.ai/docs/basics/diffusion-image.md)：生成、编辑、LoRA 加载与低显存选项；支持的操作随具体模型变化。
- [MiniMax H3 官方模型卡](https://huggingface.co/MiniMaxAI/MiniMax-H3)：H3-Base、输入模态与音视频输出；官方完整系统中的 Context-IR / 2K 模块有各自开放范围。
- [Unsloth H3 GGUF 模型卡](https://huggingface.co/unsloth/MiniMax-H3-GGUF)：量化去噪器、文本编码器与 VAE 配置；这些文件针对本地运行。
- [Unsloth H3 FP8 / INT8 模型卡](https://huggingface.co/unsloth/MiniMax-H3-FP8)：预量化推理权重与示例测试；模型文件大小不等于整套训练显存。
- [H3 音视频 LoRA 训练器](https://github.com/unslothai/unsloth/blob/f9718db128218f43b7e0b03604baa4a9a6633028/studio/backend/core/training/diffusion_h3_trainer.py)：run_h3_lora_training：加载基础权重、冻结基础参数、适配 Attention / MLP，并联合训练音视频目标。
- [H3 数据集与短片段处理](https://github.com/unslothai/unsloth/blob/f9718db128218f43b7e0b03604baa4a9a6633028/studio/backend/core/training/diffusion_h3_clips.py)：视频文件与 caption 配对；拒绝无音轨 / 全静音；当前固定训练窗为 22 帧，约 0.92 秒。
- [训练路由、资源说明与配置约束](https://github.com/unslothai/unsloth/blob/f9718db128218f43b7e0b03604baa4a9a6633028/studio/backend/core/training/diffusion_train_common.py)：TRAINABLE_VIDEO_FAMILIES、H3 配置检查、80GB+ 整流程参考、FP8 训练限制和保存 / 恢复边界。
- [Core 的 Apache-2.0 许可证](https://github.com/unslothai/unsloth/blob/f9718db128218f43b7e0b03604baa4a9a6633028/LICENSE)：核心包许可证；具体文件以自身声明为准。
- [Studio 的 AGPL-3.0 许可证](https://github.com/unslothai/unsloth/blob/f9718db128218f43b7e0b03604baa4a9a6633028/studio/LICENSE.AGPL-3.0)：Studio 与其中的 H3 训练代码使用该许可；模型权重还遵循各自的模型许可。
