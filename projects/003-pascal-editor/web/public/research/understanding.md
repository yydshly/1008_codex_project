# Pascal：房间设计平台的编辑器底座

可复用的浏览器空间编辑器，提供参数化场景、建筑构件、家具布局和实时视图；我们可以在其上建设完整房间设计产品。账号、云端项目、协作和业务规则仍需独立开发。

源码研究：c5eaf51e161ba8653204d543666f5839d6020874；运行包：1.0.3；观察日期：2026-10-08；整理日期：2026-10-12。

## 全面摘要

- **能力**：参数化建筑构件与家具布局、材质显示、2D/3D 分屏、多层查看、选择编辑和撤销重做；本地真实演示保留住宅与官方示例。

- **模块**：core 管节点、状态、注册与空间查询；nodes 提供构件、工具和几何；viewer 负责 3D；editor 负责交互与多视图；另有独立应用、CLI、MCP 与共享 UI。

- **原理**：场景以带 ID 和父子关系的参数节点保存，编辑触发 dirty 更新；构件系统重建几何、处理墙交接和门窗 CSG 开洞，再由 Three.js/R3F 渲染；2D 直接投影同一节点数据。

- **本地实现**：固定四个 npm 包 1.0.3，增加中文宿主、原创住宅、42 类本地资产、114 项材质配套资源、按示例保存的浏览器草稿和完整理解网页。

- **场景**：家装方案试排、家具商品空间展示、户型与楼层教学、房间设计产品原型；测绘参考和设施维护可以作为后续探索，需补足数据与业务。

- **价值**：复用参数—几何—视图的编辑链路，减少基础编辑器开发，把精力投入资产、方案管理、服务流程及自己的产品体验；不预设节省比例或工程精度。

- **复用路线**：可从 Viewer 展示、Editor 嵌入、独立 CLI 或 MCP 路线切入；先完成创建项目—编辑—保存恢复，再接入自己的资产目录、分享与业务规则。

- **扩展方向**：云端项目与版本、商品资产与规则、布局约束与方案比较、受控 AI/MCP、数据交换、测绘参考、自定义构件插件，以及专业服务流程。

- **边界**：官方 Next 完整托管体验尚未进入开源发行；本网站没有账号、云协作或 AI/MCP 后端，完整导出、IFC、专业施工图、真实触摸与工程校验未逐项验收。

- **验证与许可**：已实测墙厚修改及撤销重做、楼层高度保存刷新与还原、家具新增、多层展开和分屏；研究固定 c5eaf51，代码 MIT，材质单独许可待逐项核实，Basis 解码器保留 Apache 2.0。

## 能力

### 参数化建筑构件

墙、门窗、楼板、天花板、屋顶、楼梯、立柱和围栏通过类型化节点描述。用构件工具搭建，再在属性面板修改尺寸、位置与材质。

原库能力 · 墙厚编辑已实测

### 房间与建筑层级

Site、Building、Level 组织建筑，Zone 表达空间区域；构件通过 ID 与父子关系关联。住宅样板按明确楼板呈现房间，不承诺自动识别所有闭合房间。

场景模型 · 原创住宅已运行

### 家具与占地布局

真实模型可放入同一场景并继续选择、调整。原生放置提供占地碰撞检查；强制放置可越过检查，不能当作完整通行、开门或送装校验。

原库工具 · 本地 42 类资源

### 材质与空间呈现

材质槽位、贴图、环境与渲染系统共同形成可观察的室内效果。当前缓存完整 114 项目录对应的 512 分辨率贴图和缩略图，资源来源逐文件保留。

真实材质已显示 · 性能受设备影响

### 2D / 3D 对照

Editor 的多视图外壳组合 SVG 平面投影与 3D Viewer，支持平面、立体和分屏。两种视图共用节点数据；平面查看不等同于完整专业 CAD 工作流。

分屏已实测 · 同一套场景

### 楼层与室内查看

楼层叠放、展开、单层查看与相机控制帮助理解结构。cutaway 按相机方向隐藏遮挡墙，便于观察室内；官方多层示例和显式屋顶段已运行。

楼层展开与看室内已验证

### 编辑历史与本地保存

状态与历史机制支持撤销重做。本宿主通过 onLoad/onSave 按示例读写浏览器草稿；上游持久化与 CLI 的本地数据库是不同层面的存储路线。

撤销重做、刷新恢复与还原已实测

### 场景与模型交付入口

参数化场景 JSON 适合继续编辑；几何或图纸导出面向不同交付目的。发布包有导出实现，但全部格式、跨软件交换与工程精度尚未逐项验收。

保留导出入口 · 完整兼容待验证

### 组件、插件与 Agent 路线

Viewer/Editor 可嵌入自己的产品，内置节点按插件注册。仓库另有 CLI、MCP 和 Agent 工作流，为程序化操作提供路线；本网页没有启动这些服务。

组件已集成 · CLI/MCP 仅源码研究

## 原理

### 操作工具 · editor

用户选中墙，把厚度从 0.200 m 改为 0.300 m。选择、属性输入和工具交互把操作转成节点修改。

操作意图 → 参数变更

### 参数节点 · core

节点放在按 ID 索引的字典中，通过 parentId/children 形成层级。场景状态保存类型、尺寸、位置和材质引用，历史机制记录可撤销的变化。

一面墙仍是有尺寸的 wall 节点

### 标记变化 · core

更新触发 dirty 标记，相关系统处理受影响节点；对象注册表把节点 ID 与 Three.js 对象关联，方便系统与交互定位。具体依赖更新由构件系统负责。

变化传递给需要更新的构件

### 重建几何 · nodes

构件系统根据参数更新网格。墙体处理拉伸与交接轮廓，门窗依附墙体，通过 CSG 布尔减法形成洞口；家具资源按场景关系定位。

墙厚参数 → 对应的墙体网格

### 3D 渲染 · viewer

Viewer 在 Three.js/R3F 运行时中显示网格、贴图和家具，并提供相机、楼层与室内查看。数据变化最终成为新的立体画面；渲染能力仍受浏览器与 GPU 影响。

几何＋材质 → 可观察的空间

2D 平面图直接投影同一场景节点数据，不从已三角化的 3D 网格反推房间。

住宅样板实际墙节点的简化字段：

```json
{
  "id": "wall_west",
  "type": "wall",
  "parentId": "level_apartment",
  "height": 2.8,
  "thickness": 0.2,
  "start": [
    -6,
    4
  ],
  "end": [
    -6,
    -4
  ]
}
```

## 使用场景（用途分析）

### 家装方案试排

业主 / 设计师。搭建房间、调整隔墙和家具，以平面与立体图比较方案。专业尺度、规范和施工交付需另做校验。

户型编辑 · 参数调整 · 2D/3D 对照

### 家具商品空间展示

家居品牌 / 商家。把商品模型放入房间，理解搭配和占地关系；商品 SKU、价格、供货和送装规则由业务系统提供。

资产目录 · 家具放置 · 材质展示

### 户型与楼层教学

教学 / 建筑入门。通过选择构件、楼层展开和视图对照说明空间结构，制作可继续操作的案例。

层级组织 · 多视图 · 参数观察

### 房间设计产品原型

我们的产品团队。复用编辑器，优先做项目保存与重新打开、资产管理、分享和适合用户的设计流程。

组件集成 · 场景数据 · 宿主服务

### 现状空间与测绘参考

勘察 / 空间数字化。固定源码有 Guide、Scan 与 capture 相关路线，可探索以图像或扫描为参考组织方案；坐标、标定和采集链路未在本演示验证。

源码扩展路线 · 需核对目标发行版本

### 空间服务与设施维护

装修服务 / 物业。将构件与维护记录、任务或设备信息关联，形成面向空间的服务入口；工单、设备数据和专业标准需要独立建设。

用途分析 · 参数对象与业务关联

## 可扩展方向（待开发）

### 云端项目、版本与分享

基础：现有模型、缩略图、尺寸元数据和放置工具。

验收：已知尺寸对照正确，模型快速载入，位置、占地和业务信息能对应。

推进：内容与业务适配。

### 布局约束与方案比较

基础：参数构件、Zone、占地查询与可保存方案。

建设：通行距离、开门范围、候选布局、差异对照和适合业务的规则。

验收：用人工核对的案例测试；区分占地碰撞与高度、通行、施工约束。

推进：设计辅助。

### 受控的 AI / MCP 设计

基础：固定仓库的 MCP 工具路线和可编辑场景。

建设：连接目标服务、核对工具版本、上下文、权限、操作记录与场景验证。

验收：对比修改前后节点，检查尺寸和资源；失败能回退，生成结果可继续编辑。

推进：Agent 独立试验。

### 数据交换与工程交付

基础：结构化节点数据以及包内模型、打印导出入口。

建设：选择目标格式、单位与语义映射、版本兼容、资产归档和验收基准。

验收：在目标软件中重开并核对尺寸与内容；IFC、专业施工图和报价逐项验证。

推进：按业务选格式。

### 图像、扫描与现状参考

基础：源码中的 Guide/Scan 和 capture 扩展契约。

建设：采集来源、坐标标定、尺度对齐、流传输、访问控制与异常恢复。

验收：先核对目标包是否有接口，再用已知尺度场景测试；不承诺自动精确重建。

推进：数据接入试验。

### 自定义构件与插件

基础：节点定义、schema、渲染器、工具和系统注册。

建设：开发业务构件，补齐参数面板、几何、空间查询和数据迁移。

验收：新增、修改、撤销、保存、重开与多视图都保持一致。

推进：开发者扩展。

### 面向空间的专业服务

基础：构件 ID、层级和可附加元数据。

建设：将设备、工单、装修服务或资产台账与节点关联，补齐角色、流程与审核。

验收：空间对象与业务记录一致；业务判断由专业规则负责。

推进：产品与服务扩展。

## 边界

- 研究 Commit 与 npm 1.0.3 分别固定，未逐文件核对；源码中的新接口不能自动视为本地发行包已有能力。

- 官方 Pascal Next 是独立托管预览，其完整住宅、剖切、X-ray 和漫游体验尚未属于开源编辑器发行版。

- 本网站部署静态理解页与编辑器，没有账号、云端项目、协同服务器、CLI 数据库或 AI/MCP 服务。

- 浏览器草稿按站点来源隔离；localhost 与公开站点不会自动共享。重要方案需自行导出备份并核对支持的格式。

- 全部建造工具、导出格式、IFC、真实触摸、跨浏览器、大场景和工程精度没有逐项验收。

- 代码 MIT 和素材许可分别记录；部分材质的独立来源许可尚未逐项核实，不能自动把全部贴图认定为 MIT。
