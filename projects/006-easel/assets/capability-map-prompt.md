# Easel 能力全景图生成规格

使用内置 image_gen，分类 infographic-diagram。根据固定源码与本子项目研究资料，制作一张中文知识信息图；不作为 Easel 原产品截图或端到端实测效果。

## 视觉与布局

制作一张高信息密度但秩序清楚的中文竖版长图，目标 2160×3840 或最高可用的 4K 竖版分辨率。精致的编辑式技术知识地图，浅色纸面、深蓝标题、青绿主线、橙色小提示；清晰的中文无衬线字体，不用艺术字体。所有文字必须准确，禁止伪文字和编造信息。整个图是一张完整海报，不画成网页截图，不出现浏览器或电脑外框。保留充足分栏和行距，文字可放大阅读；装饰适度，空间优先留给内容。

从上到下严格分为：标题和目标；账号画像驱动的七步闭环；信息获取与过滤；六类全部技能目录；执行原理；使用场景、扩展方向和对研究者的意义；实现边界与出处。技能目录使用紧凑的分组条目，多列排版，制作类 52 个单独使用两到三列，确保 114 个技能名称全部出现且不重复、不遗漏。不要替换成示意占位，也不要声称这些全都通过运行测试。

## 账号画像与七步闭环

中央或上方核心：“账号画像：定位 / 风格 / 受众 / 平台 / 偏好 / 记忆”
核心说明：“六份 Markdown 文件作为上下文，OpenClaw Agent 按任务组合技能”

5. 检查与多平台发布 — 人设 / 质量 / 风险、平台改编、预览确认

## 信息从哪里来（准确区分来源和发布）

标题：“信息入口主要面向国内中文平台”
热榜六源：“微博、抖音、知乎、B 站、百度、今日头条”
获取原理：“Web 热榜由第三方 60s.viki.moe 聚合；微博、抖音、B 站、百度有 xxapi 备用。”
规则：“缓存 300 秒；保留源顺序，取前 1–30 条；失败可旧缓存。Web 热榜接口不按画像或关键词过滤。”

资讯十一源，全部逐项出现：“36氪快讯、华尔街见闻、腾讯新闻、人人都是产品经理、虎嗅、钛媒体、极客公园、少数派、InfoQ 中文、AIHOT、澎湃（FeedX 转接）”
获取原理：“8 个 RSS + 3 个网页 / JSON 解析器；这是一组固定 source key。”
规则：“资讯关键词仅匹配标题，逗号 OR；AIHOT 24h、澎湃 48h，时间无效时保留。命中不足 5 条可放宽关键词，标记 smart_fill。”

其它路径：“自定义 RSS / Atom：用户提供 feed；标题 + 摘要筛词，按链接去重、时间排序。”
网页研究：“UGC、竞品、平台规则：web_search → web_fetch → Agent 核对。按品牌 / 问题 / site: 查询；官方、行业、社区证据分级。”
搜索目标：“UGC：小红书 / B 站 / 微博 / 知乎等；规则：国内六平台创作者中心，newrank.cn / woshipm.com / 36kr.com 等。”
补充参考：“小红书热榜、每日新闻、IT / AI 资讯另见参考文档，未接入 Web 六源。”
小提示：“程序取数与过滤，画像相关度与选题价值由 Agent 继续判断。”

## 三列：场景、扩展价值、对你的意义

使用场景（现有能力）：
1. 垂类账号日更：领域资讯 → 选题 → 图文 / 短视频。
2. 技术 / 知识传播：GitHub 项目、论文、文章 → 卡片、长文、讲解视频。
3. 素材再利用：直播、讲座、口播 → 转录、切片、字幕、多平台版本。
4. 品牌 / 小团队运营：活动、日历、改编、发布记录、评论与月度复盘。

可扩展价值（研究建议）：
1. 加入海外媒体 / RSS 与新搜索源；海外平台发布另做适配。
2. 增加主题分类、统一去重、来源可信度和可追溯引用。
3. 替换模型、媒体模板、TTS 与发布适配器，复用技能接口。
4. 将 JSON 队列接数据库 / 外部调度，增强失败重试与真实反馈回流。

对你的意义（结合当前开源项目研究）：
1. 把已有 GitHub 研究转成技术图文、演示视频与持续知识内容。
2. 借鉴“画像 + 技能 + 工具”分工，搭建自己的内容工作台。
3. 按需复用检索、卡片、剪辑、发布模块，积累可组合资产。
4. 先验证“小规模检索 → 脚本 → 成品 → 人工预览”，逐步补发布与复盘。
