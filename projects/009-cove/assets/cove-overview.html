01

它提供什么？

提供全栈起步基础，省去从零集成的工作。

页面与全栈
React + TanStack Start

服务端渲染、服务器函数、API 路由；浏览器水合后接管交互。

路由与数据
TanStack Router + Query

文件路由、类型化导航、预加载、缓存、去重及 SSR 数据衔接。

账号与会话
Better Auth

邮箱密码注册 / 登录 / 退出；GitHub、Google 登录入口需配置凭据。

数据库
Drizzle + PostgreSQL

认证表、关联、服务端连接与迁移工具；业务表由自己新增。

基础界面
Tailwind + shadcn/ui + Base UI

表单、按钮、通知、主题切换；默认 /app 是用户展示示例。

开发与运行
Vite+ + Nitro + Varlock + evlog

构建部署、环境变量验证、请求日志，以及 Vitest / Playwright 测试基础。

业务仍要开发：项目 / 订单 / 笔记等业务表和页面、业务规则、角色与资源权限，以及按需增加的支付、存储、邮件、AI 和队列。

03

模板自身的架构：模块如何搭配

已有调用关系需显式接入的中间件

认证操作入口

authClient → /api/auth/* → auth.handler

邮箱密码、退出和 OAuth 回调由 Better Auth 处理；通过 Drizzle adapter 保存账户与会话，响应设置 Cookie。

读取当前用户入口

Query → $getUser → _getUser → getSession

读取当前请求头，返回 user 或 null，并转发 Set-Cookie；SSR 直接执行，浏览器通过服务器函数 RPC 请求。

页面与服务器边界

_auth.beforeLoad / authMiddleware

页面未登录时跳转 /login。私有业务函数或 API 必须显式鉴权，再检查角色与 ownerId / tenantId；页面检查不会自动保护接口。

数据与运行支撑

认证四表 / Vite+ / Nitro

现有表：user、session、account、verification。Vite+ 组织构建，Start 分离执行边界，Nitro 运行 SSR、API 和日志。

Varlock / ENV：校验配置、生成类型；服务端密钥留在服务器。

Nitro / evlog：承载服务器请求，记录结构化日志；投递平台按需接入。

Vite+ / 测试：开发、构建、检查；轻量测试基础，业务验证需要补齐。

SSR 与水合

服务器先准备 HTML 和数据，浏览器恢复状态并接管交互。Router、Query、组件与 loader 可能参与两种环境。

服务器函数 / RPC

createServerFn 的实现留在服务器，浏览器构建中替换为网络代理。数据库模块声明 server-only，浏览器不直接连数据库。

两层缓存

Query 默认两分钟新鲜期，减少浏览器请求；Better Auth Cookie 缓存五分钟，减少查库。freshAuthMiddleware 跳过会话缓存。

认证与业务授权

会话回答“是谁”，业务规则回答“能做什么”。中间件需挂载；角色、资源归属、操作权限和输入校验由业务代码负责。

05

从模板到自己的产品：六步完成适配

“拿来使用”包含实际的前后端开发。先做一个完整业务闭环，再增加复杂服务。

01创建自己的项目

用模板或 pnpm create cove 初始化；替换名称、首页、示例账号说明与默认 /app。保留所需基础，删去不需要的示例。

02接好实际运行配置

准备 Node.js、pnpm、Vite+ 与 PostgreSQL；配置 base URL、数据库 URL 和认证密钥。使用社交登录时再配置 OAuth 凭据与回调。

03设计业务数据模型

增加项目、笔记、订单等表与关联；生成并应用迁移。定义 ownerId / tenantId、数据约束和权限规则。

04完成一个业务闭环

页面 → Query → 业务服务器函数 / API → 身份与权限校验 → Drizzle。实现创建、读取、更新、删除及缓存同步。

05按需求接业务服务

收费接支付 / 权益；附件接对象存储；通知接邮件；AI 接模型 / 任务队列。接口、凭据和失败处理都需实际实现。

06验证后部署与维护

测试注册登录、权限、数据变更和关键业务流程；验证构建、数据库连接与平台部署，再补日志监控及依赖升级策略。

启动参考（固定 README；先准备运行工具与数据库）pnpm create cove→ 进入项目并填写 .env.local →vpr env:load→vpr db generate→vpr db migrate→vpr dev

适用边界

纯静态介绍页可以更轻量；复杂电商、ERP、实时协作等可继续开发，但专门的领域功能和基础设施仍需设计。认证四表不等于业务系统，verification 表存在也不等于验证邮件已经接通。

运行与版本条件

原模板：Node.js ≥ 24、pnpm ≥ 12、Vite+、PostgreSQL。固定版本含 Drizzle 1.0.0-rc.4、Nitro v3 beta；采用时验证目标平台兼容性。package.json 的 0.0.1 不代表稳定正式发布。
