    技能转化为哪些规则？

    核心循环、手感和 UI 规范落实为 0.22 秒格挡窗口、气息消耗、闪避冷却、一次破绽一次强反击。代码执行这些边界，技能文档指导设计和验收。

    风格由什么构成？

    第二版用内置图像工具生成干笔山水与完整人物姿态，接入脚底锚点、状态选帧、衣摆和笔触刀光；题款与朱砂印贯穿 UI。素材和规则具体进入游戏，模型参数没有修改。

    实际证据说明什么？

    真实键盘接招六次，完成三阵；失败重开、手机按钮、十项模拟和十一份画面检查通过。证明技能可用于另一类小游戏，尚未量化相对直接开发的收益。

    库具体提供了什么？

    Director 提供制作顺序与产物契约；gameplay 提供工程起点、手感与碰撞选型；graphics 和 UI 提供视觉层次、状态反馈和触控规范；debug / QA 提供诊断、画布检查与证据协议。

    模型还需要做什么？

    运输机制、关卡航线、港口模型、界面与音效仍由本次开发实现。技能没有自动生成这款成品。比如能源信号被雾冲淡，仍需观察实际画面并修正。

    这次证明到哪里？

    证明可以把技能用于新游戏并跑通交付。通关录像使用真实键盘，没有进度注入；六份状态截图用于画面检查。尚未做同模型对照，不能据此量化省时或品质增益。

      如何约束，以及约束到哪里

      指导、提示、校验的强度不同。

      文字规则依靠模型遵循；机器检查覆盖明确定义的契约；审美与好玩仍需观察和试玩。

      使用时仍需处理的限制

      • 模型负责解释需求、写代码与取舍；技能包没有改变模型参数，也不能启用宿主未开放的工具。
      • Tripo、Gemini、ElevenLabs 需要可用密钥、权限和额度；本次没有调用这些付费生成服务。
      • 自动试玩需要按游戏改写。浏览器模拟的手机布局不能证明真实手机运行性能。
      • 本机首次 npm ci 遇到模板锁文件不一致，已在副本修复；Node 辅助测试有一项因 Windows 符号链接权限失败。
      • 素材服务、Three.js 和浏览器版本会变化；工程、配方与 API 接口都需要维护。

      什么情况下适合用

      用在规模可控、需要完整交付的交互项目。

      根据源码与两次实验归纳的应用判断，
      每种场景仍有自己的验收条件。

      任务变大时，需要继续补充系统。这套技能不是完整大型游戏引擎。多人网络同步、账号服务、复杂关卡与经济系统、反作弊等，需要单独设计。AAA 命名表达画面目标，不是质量认证；真机性能、素材版权与上线条件也要分别确认。

      直接让模型开发，区别是什么

      增量价值取决于你已提供什么。

      基于源码的判断：通用知识提示的增益可能随模型提升而缩小；可复用的工程、服务封装和检查工具仍能减少重复搭建。是否净省时间、少返工或提高品质，需要对照实验。

      建议固定同一模型、相同需求、资源、预算和时间，比较“简短需求”“详细需求与验收”“详细需求加技能包”三组，记录可玩行为、缺陷、人工纠正次数、耗时和成本。本项目没有将作者演示当作增益量化证据。
