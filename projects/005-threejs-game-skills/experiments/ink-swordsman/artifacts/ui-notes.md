# 竹影问剑：界面与输入制作记录

本次 UI 为独立原创实现。实际读取上游固定提交 `8286774b22a2566bf894dbc825825c16921866af` 的 `threejs-game-ui-designer/SKILL.md` 与 `references/ui-patterns.md`，沿用其“生存 → 目标 → 即时反馈”的层级、真实状态驱动和触屏输入取消规则。没有使用外部字体服务、图片或付费生成服务。

## 美术与状态

- 暖纸底上用黑墨生命标记和细线气息条；敌人生命、危险与反击共用朱红。菜单以一张可滚动卷页呈现，桌面右侧保留场景；没有仪表卡片、霓虹色或运输游戏布局。
- 顶部显示五格生命、气息、对手名称与生命、三轮进度和剩余时间。中下方仅保留危险 / 反击提示及一条来自真实状态的事件反馈。
- 覆盖卷首、交锋、暂停、胜利、失败、重开、音效和减少动态；`#app[data-mode]` 与模拟状态同步。UI 只读 `UiFrame`，通过 `UiIntent` 发送操作，不修改战斗数据。
- 每个菜单状态有主动作、键盘焦点圈与焦点循环；开始和继续后聚焦游戏画布。Escape 由 UI 独占，避免同时暂停又继续。

## 输入与响应式约束

- A / D / 左右键持续移动；J / K / L / 空格按键边沿触发攻击、格挡或闪避，忽略按键重复，每次 `read()` 消费动作。键盘焦点在菜单按钮、链接或表单上时不驱动角色。
- 手机方向键按住移动，斩 / 御 / 闪按钮在真实 `pointerdown` 时触发一次；捕获指针，处理抬起、取消、丢失捕获、窗口失焦与页面隐藏，防止粘住输入。
- 移动按钮 48 × 52 CSS px，动作按钮 56 × 66 CSS px，暂停 44 × 44 CSS px；320–360 px 窄屏仍不低于 44 px。安全区域通过 `env(safe-area-inset-*)` 纳入上下左右边距。
- 桌面 HUD 在顶部约 90 px；手机顶部约 110 px、底部约 100 px 是状态与按键区域。菜单在矮屏与窄屏可滚动，短数字使用固定宽度与等宽数字。
- 未新增独立动画循环，角色动作、伤害、危险和反击均由主循环提供的真实帧决定；生命受损的短暂透明度反馈尊重减少动态设置。

## 文件与验证边界

修改范围：`index.html`、`src/styles.css`、`src/ui/InkUI.ts`、`src/core/InkInput.ts` 和本记录。新程序化场景与战斗逻辑由其他模块实现。

静态尺寸、事件生命周期和接口已核对。实际生产截图、桌面键盘 / 手机指针输入、菜单文字适配、胜败重开和子路径返回由主流程合并验证；这些运行结果以最终验收报告为准，本记录不预先宣称浏览器或手机硬件验证通过。
