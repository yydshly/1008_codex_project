# 竹影问剑 · 第二版绘画资产与运动

用户指出第一版过于简单、水墨武侠风格不鲜明。此版在保留全部战斗规则与输入的前提下，替换了人物和环境表达。使用固定提交 `8286774b22a2566bf894dbc825825c16921866af` 的 graphics skill 及全部四项 references，并实际查看 scene-1 / scene-2 / scene-3 的质量校准图片；不以代码量为美术质量证据。

## 素材与实现

父流程使用内置 imagegen 为此次实验生成原创手绘场景与角色动作图集。最终运行使用 `scene-v2.png`、`hero-atlas-v3.png`（闲置、步态、格挡、闪避、受创五姿态）、`enemy-atlas-v3.png`（九姿态）及独立 `hero-attack-v4.png`。全部原始资产、六次生成和布局修正记录见父项目 `assets/ink-art/README.md`。此版不是完全程序化美术，也未引入外部付费 API、下载角色或第三方贴图。

`InkWorld.ts` 继续提供 `createInkWorld(scene)` 返回 `update(WorldFrame)` / `dispose()`。全部计时来自主 Game 循环，图形模块不创建独立 rAF、输入或命中规则。

- 绘画背景以真实纹理渲染，与少量前景竹叶、漂叶形成深度；实际 `scene-v2.png` 为 1672×941，台面线约 y642（68.2%）映射为地面 `y=0`。按当前相机的可见范围等比扩展画片覆盖手机纵向画幅，保留脚线和图像比例，不修改相机。
- 主角六姿态与三名敌人的三姿态通过真实 action / progress / moving 选择；朝向由 x 缩放镜像，脚底锚点逐格校准，避免格子留白造成漂移。攻击前 26% 是预备，中段 52% 显示独立攻击图，最后 22% 回到低剑恢复，覆盖实际 0.13 秒命中时刻。
- 用 alpha>32 的连通主体识别实际包围盒，再加约 8 像素透明边距，采用显式 UV Rect 而非硬切等分格；脚底用主体最下方 35 行 alpha>128 像素的左右中点及最低 y 校准。v3 敌人的宽衣袖会侵入名义列分界，显式区域避免带入邻帧衣袖。主角格挡从 x590 开始，不带入旧图攻击刀尖。
- 同一图集内使用固定世界单位/像素保持人物体量，独立横向攻击图按实际身体高度 851 像素映射为 3.91 单位，不把 1536×1024 整图缩成一格；刀尖完整保留，脚锚实际像素为 (652,943)。
- 衣袍次级运动在 MeshBasicMaterial 的共享 shader 程序中注入，位移权重从脚底零逐渐增加，装饰动态遵循 reducedMotion。真实动作和预告仍保留。
- 刀弧、干笔划、墨滴与破墨格挡光来自 slash / enemySlash / impact / parryFlash；64×64 共用颗粒纹理及少量局部 ShaderMaterial 控制边缘扩散与墨色透明，不新增全屏后处理、灯光或阴影。
- 警示保持朱红地面刀势，重斩增加双笔与三笔标记，同时区别色彩与形状，避免依赖颜色本身。

## 当前核验

最终接口通过 TypeScript 检查，Node 运行 900 帧动作组合，检查 UV 在 0～1、三个敌人行匹配零起始 stage、攻击分段选帧、全部世界矩阵有限与几何/材质/贴图释放。CPU 场景有 23 个 Mesh、21 个几何、13 个材质、5 张贴图、约 1,856 三角形；该数值不等于 GPU draw call 或帧率。Node 无图像 DOM，资源明确报告 placeholder，不冒充加载成功。

实际看过三张初始源图，并用 pngjs 核对 RGBA：场景全不透明；hero-v2 角像素 alpha0，弱暗雾 alpha1～12 共 133,369 像素，材质 alphaTest=.05 去掉这一弱外围。初始 hero-v2 的攻击刀尖跨过列分界，enemy-v2 的高举刀和斩击也跨格或碰到边界，因此没有将它们直接作为正确图集验收。父流程使用 imagegen 修正布局，修正图到位后按实际姿态和脚底锚点重新校准。

实际看过两张 v3 图和独立 v4 攻击图，并用 pngjs 的连通 alpha 像素核对所有 UV 区域及脚锚。资源接口提供 `ready:Promise<void>`，四张 PNG 任一失败会 reject；`getDiagnostics()` 报告真实 ready、loaded、资源尺寸/状态、heroPose、enemyPose 和实际 UV 区域。浏览器桌面/手机画布、shader 编译和指标由父流程整合核验；此时不宣称已达到 premium / showcase 门槛。

父流程完成 11 份实际 GPU 检查，四项绘画资源 ready，shader 无编译错误；实际主动、攻击、手机与重斩画布未见黑框、串帧、裁剑或明显漂脚。最终敌人击败后，模拟在胜利状态停止，原 progress 仍为 0 会留下站立人物；仅在图形模块将 won 的 defeated 姿态呈现为进度 1 并完成淡出、隐藏接地墨影，不修改 Simulation 或传入 frame。最终生产画布由父流程再确认。
