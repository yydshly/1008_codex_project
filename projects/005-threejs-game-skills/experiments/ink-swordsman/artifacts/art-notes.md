# 竹影问剑 · 程序化图形制作记录

图形模块为此次实验原创，只参考制作技能的流程，不复制上游游戏美术。使用固定提交 `8286774b22a2566bf894dbc825825c16921866af` 的 `threejs-aaa-graphics-builder/SKILL.md`、`references/authoring-recipes.md`、`references/technical-art.md`。上游 Three.js game skills 为 MIT；当前没有调用外部图像、模型、付费生成服务或下载素材。

## 制作方式

- 世界采用 XY 平面的侧视纸戏。512×512 固定种子 `DataTexture` 以纸浆、纤维与细颗粒生成暖纸底；三层形状几何远山、低透明度雾笔、淡月、竹枝、石径形成前中远景。
- 主角有斗笠、笠骨、帽绳、面部、前后衣袖、衣襟、布褶、朱红腰带、带尾、分段腿脚、绑腿、刀鞘式刀柄、护手与弧刃。轮廓通过多边形和笔画几何设计，不使用方块人的拼装轮廓。
- 敌人三个阶段分别显示束发、宽肩甲、尖兜帽长披带，轮廓随零起始的 stage（0 / 1 / 2）变化；危险同时用红色地面刀势与重斩三笔上方标记表达。整合时纠正了最初将阶段按 1 / 2 / 3 解释的接口误差。
- `FighterFrame.action / progress / moving` 驱动关节、衣袍和刀角；实现攻击、格挡、闪避、受创、蓄力、斩击、收招、失衡和倒下。步态按当前移动状态呈现，不决定移动或伤害。
- 墨刀弧来自 `slash / enemySlash`，接触墨点来自 `impact`，格挡接点来自 `parryFlash`；没有自动命中或独立效果计时器。所有更新由主 Game 循环调用。
- 竹林每组按竹干、关节、叶子合批；落叶、墨点用 InstancedMesh。共用墨色、布色、纸色、朱红材质，不增加动态灯光、真实阴影或全屏后处理。MeshBasicMaterial 关闭 toneMapping 与 fog，保证墨色和朱红在现有渲染器下可读。
- 减少动态开启后装饰时间固定，停止落叶、竹摆、衣摆风动；必要动作、预告和命中反馈仍显示，格挡闪光和墨点扩散降低幅度。

## 验证与边界

2026-10-09 图形模块通过 `npx tsc --noEmit`。Node 使用当前 Three.js 0.184 创建真实 Scene，交叉运行 5 个主角动作 × 6 个敌人动作 × 5 个进度 × 3 个阶段 × 2 个动态设置，共 900 帧，检查所有世界矩阵为有限值，并检查连续两次 dispose 后场景清空、原背景和雾还原、所有几何/材质/贴图释放事件各发生一次。首次检查出现未传贴图的 `map: undefined` 警告，已改为显式 null 后复核。

该场景包含 121 个 Mesh 对象、120 个几何、31 个共享材质、1 张贴图，含实例的几何总量约 4,396 三角形。检查帧中 111 个 Mesh 及其父级均可见。这是 CPU 场景统计，不是实际 draw call、GPU 内存或帧率；浏览器桌面/手机画面、真实输入时序、Renderer.info 指标由主流程在整合版本核验。本说明不把 Node 场景构建当作最终效果验收，也不宣称 AAA 质量。

## 实际画布复核与修正

整合后查看 `pass-1/desktop-windup.png`、`desktop-counter.png`、`desktop-late-run.png`、`mobile-active-play.png`：纸底与分层远景可读，边侧竹林未遮挡双方，重斩的三笔标记和双地线同时区别普通斩击。发现 idle 的长刀横伸，使蓄力画面看起来已经刺入对方腰部；改为低位斜持刀，并调整闪避的屈肘握刀以保持刀尖离地。格挡圈原先因错误夹紧接点距离而位于主角胸前，改为双方中点；伤害墨点跟随当前受创或失衡者。此处只修图形姿态和效果位置，不改命中距离、格挡窗口或伤害。

手机截图的人物显著小于桌面，主流程负责缩小近距离镜头范围并按双方距离适配，图形模块不修改相机。上述四帧为第一版截图，修正后应另取真实帧复核。主流程第一轮真实 GPU 检查报告预算通过；具体调用数与 GPU 指标以整合版本报告为准。
