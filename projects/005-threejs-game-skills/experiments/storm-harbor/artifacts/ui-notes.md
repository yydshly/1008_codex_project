# UI 与输入实施记录

本实验真实读取固定提交 `8286774b22a2566bf894dbc825825c16921866af` 的 `threejs-game-ui-designer/SKILL.md`、`references/ui-patterns.md`，以及 gameplay 的 `references/game-feel.md`。这些规范指导本实验新增代码；游戏 UI 和输入实现不是上游提供的成品。

## 规范落实

| 上游要求 | 本实验实际实现 |
| --- | --- |
| 生存状态 → 任务进度 → 即时反馈 → 风格层次 | 顶部艇体四格与封港倒计时，其次交付六格、装载两格；热量与 EMP 使用窄条仪表；事件提示避免横跨水域 |
| 游戏界面而非网页统计卡 | 工业港区仪表、航向刻度、薄钢板边框、紧凑地图；橙黄救援、青绿能源、珊瑚危险统一色彩角色 |
| UI 读取唯一状态并发送意图 | `HarborUI.update(UiFrame)` 只更新显示；开始、暂停、继续、重开、菜单、静音、减少动态仅发 `UiIntent`；没有写入模拟状态 |
| 状态完整 | 中文菜单与任务简报、实际航行 HUD、暂停/恢复与设置、胜利统计、失败原因与重开；外部素材不加载，因此没有虚假的资产加载条 |
| 固定数值空间与可滚动菜单 | 倒计时、交付与装载保留固定字宽和 tabular numerals；菜单面板有视口高度上限、内部滚动；长失败原因可自然换行 |
| 手机输入与键盘同一语义 | 摇杆与 WASD/方向键产生 `Controls.x/z`；右侧加速与 EMP 对应 Shift/Space；向上为世界 `-z`；合并方向的向量长度不超过一 |
| 触控取消与失焦必须释放 | `pointerup`、`pointercancel`、`lostpointercapture`、窗口 blur、文档隐藏均处理；`clear()` 清除键盘、摇杆、排队 pulse、按钮状态和指针捕获 |
| 触控目标约 44 CSS px 及安全区域 | 暂停 44×44、摇杆 112×112、加速/EMP 66×79、主操作与设置至少 48 高；`env(safe-area-inset-*)` 保护四边，按钮间距 10 px |
| 反馈不能遮挡下一个决策 | 拾取和交付仅短促放大相应数字，伤害仅艇体局部淡入；减少动态开启时关闭这些动画；不阻塞输入 |

## 文件与集成

- `index.html`：中文状态界面及 `harbor-*` 专用 DOM，保留主画布 `game-canvas`；生产 `play/` 页面通过 `../` 返回研究页。
- `src/styles.css`：桌面边缘 HUD、390 px 手机上下布局与窄屏回退；移除模板的 Relays/Time/Dash HUD。
- `src/ui/HarborUI.ts`：状态显示、意图发送、焦点管理、全局港区简图。地图读取真实玩家、能源和巡逻机位置，平台与基地读关卡常量。
- `src/core/HarborInput.ts`：同一语义的键盘/指针控制及释放生命周期。`read()` 单次消耗 pulse；Game 负责将短促事件锁存至下一个固定步长。

菜单首次出现时聚焦主要操作，Tab 在面板中循环；开始/恢复时焦点回到游戏画布。界面按钮获得焦点时，输入层不拦截空间键或方向键，保留按钮激活和菜单滚动语义。Escape 由 HarborUI 独占处理，P 由 Game 处理，防止一次按键发生两次状态切换。基地使用与实际港口一致的青绿信号色，地图用大方块与环区分能源菱形。

## 当前验证范围

2026-10-09 执行 `npm.cmd run build`：strict TypeScript 与 Vite 生产构建通过。图形和模拟已集成，浏览器的实际出航、暂停、失败重开、桌面及 390×844 布局由主流程统一验证并保存截图。本记录中的 CSS 尺寸是实现约束，不能代替最终浏览器的遮挡和真实触控检查；最终证据以主流程的运行报告为准。

没有为本 UI 调用付费素材生成 API；图标与仪表由 HTML/CSS 和小型 Canvas 简图实现。上游原始模板继续单独保留，未将本实验成品误标成原库自带效果。
