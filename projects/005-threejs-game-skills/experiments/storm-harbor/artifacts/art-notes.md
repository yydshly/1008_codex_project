## 技术选择与性能边界

海水使用低幅度 CPU 顶点波浪和标准 PBR 材质，不涉及自定义 shader；没有 shader-cookbook 未验证配方。共有材质合并代替逐对象 draw call；有独立状态的目标、巡逻和货物保留可切换节点。静态部分约十余次材质调用，动态角色和信号预计总调用在 150 内，但这只是代码预算，必须以整合后的真实最坏视角 `renderer.info` 为准。阴影、水面法线重算和透明材质仍有开销，具体数值由父流程测量记录。

没有现有游戏截图可当作改进前基线，因此不制造“前后提升”图片，也不宣称此实验达到了 AAA 或商业美术品质。这次可见效果证明的是技能指令实际转化成了一个原创可玩场景，不证明相对其他模型的量化增益。

## 校验范围

2026-10-09：`node node_modules/typescript/bin/tsc --noEmit` 对图形文件未报告错误；集成当时 UI 与输入模块仍在并行实现，项目级编译报缺失模块，交由父流程完成后再跑。另用实际 Three.js 0.184 在 Node 建立 scene、执行两种 WorldFrame，再 dispose：构建、目标隐藏、未启用巡逻隐藏和根节点释放均通过。初始完整资产包含 85 个 mesh / geometry、28 个 material，约 30,180 三角形；这是资产清点，**不等于**浏览器实测 render calls（阴影、可见性与当前关卡状态会改变调用）。

所有暂存几何在合并后释放，`dispose()` 释放世界几何、材料和阴影图并恢复 scene 背景与雾。截图、实测渲染指标和最终完整构建结果由父流程补入验证报告。

## 聚焦修正：目标与危险的实际相机判读

检查真实游玩截图 `../../../assets/harbor-active.jpg` 后，发现两项具体缺陷：青绿能源与返航圈退成灰白，红巡逻机与橙色玩家不够区分、扫描圈过淡。根因是正交相机到水面的距离已超过雾起点 37 米，让 gameplay 信号混入灰蓝；高强度光照和 ACES 又淡化浅色标准材质。

本轮只修对应角色信号，环境雾、照明、相机、关卡和碰撞契约保持原样。奖励及状态标识使用不受雾与色调映射影响的共享 Basic 材质，青绿匹配 HUD 的 `#60e2c4`，危险红匹配 `#ff8277`。能源添加窄小竖向灯标、略加厚底环；返航区加厚圈、使用清楚的导航箭头与两根轻小导航灯；巡逻主体改深珊瑚红，扫描圈加宽并提高透明度到 .78。没有新增全屏发光或后处理。

`node node_modules/typescript/bin/tsc --noEmit` 完整通过。真实 Three.js 构建与释放复查通过；完整资产由 85 增至 93 个 mesh，三角形约 30,680。新增形状仍按材质批量合并，预计不会突破 150 调用预算；最终渲染计数与颜色修正效果由重新构建后的真实浏览器 QA 确认，不能把资产清点当作实测性能结论。
